# Feishu Work Twin

本地飞书工作数字人：使用个人账号接收消息，通过本地 CLI 或模型 API 处理会话，并提供本机网页工作台。

基于 [cv-cat/LarkAgentX](https://github.com/cv-cat/LarkAgentX) 二次开发。保留原项目历史与协议实现，原始说明见 [README.upstream.md](README.upstream.md)。

## 功能

- 私聊、群聊分别配置默认回复方式；联系人和群可跟随默认，也可单独指定。初始均为不回复。
- 连续短句按最后一句后的停顿合并；群里单独 @本人时带上同一话题的前文和近期图片。
- 私聊支持自动回复、仅草稿或不回复；群聊支持不回复、仅 @我、仅 @全体或自动回复。
- 人工发送后，该会话暂停自动回复，默认 2 分钟，可在数字人设置调整（0 为关闭）；暂停期间的新消息按最后一次活动延长计时，旧消息不会到期补发。
- 会话概览、有效记忆、联系人角色与回复风格、异常与待办管理。
- 网页支持图片、表情包、图文消息显示，以及图片选择、粘贴、拖入、混排和发送前预览。
- AI 回复润色、文字尾缀、执行记录、左下角数字人入口及居中聊天窗口。
- 数字人控制台可查询工作、创建或完成待办，以及按明确指令发送消息；已建立的会话才能作为收件人。

## 安装与启动

需要 Python 3.11+、[uv](https://docs.astral.sh/uv/)。CLI 模式需安装对应工具；API 模式不需要安装 Codex。

```powershell
git clone https://github.com/jadenjin/feishu-work-twin.git
cd feishu-work-twin
Copy-Item .env.example .env
uv sync --locked
# 使用 Codex CLI 时先登录；使用 API 可跳过
codex login
uv run lark auth qr
uv run lark web --port 8765
```

打开 http://127.0.0.1:8765/。Windows 推荐手动运行 `start-workhub.ps1`，守护和网页服务通过 `pythonw.exe` 无窗口运行，启动完成后可关闭启动终端；重复运行不会启动第二个监听实例。模型 CLI 和超时清理命令也不会弹出控制台窗口。`uv run lark web` 仍为前台运行。更新前已有的有窗口守护需要先执行 `-Stop`，再手动启动以应用新方式。

也可以双击程序目录的 `start-workhub.cmd` 启动。成功后启动窗口自动关闭；失败时保留窗口显示错误。入口输出单独保存在程序目录 `data/logs/workhub/startup.log`，便于排查依赖或启动参数错误。`start-workhub.ps1` 使用带 BOM 的 UTF-8，兼容 Windows 自带的 PowerShell 5.1 与 PowerShell 7。

```powershell
.\start-workhub.ps1          # 后台启动并守护
.\start-workhub.ps1 -Status  # 查看守护和服务进程状态
.\start-workhub.ps1 -Stop    # 正常停止服务和守护，不再重启
```

服务异常退出后自动重启，连续失败按 2、4、8、16、32、60 秒退避，稳定运行 60 秒后重置退避。主动停止或正常退出不重启；停止时先通知网页服务清理连接，30 秒仍未退出才终止其进程树。守护本身不设置开机自启。

默认运行锁和守护状态保存在程序目录的 `data/run/`，不受用户目录视图、所选消息数据目录或启动工作目录影响。`-Status` 会显示实际状态文件路径，并校验守护 PID 的存活状态和进程创建时间；停止后 PID 显示为空，记录损坏或 PID 被复用时显示未知状态，不把旧记录当成当前实例。设置 `LARKX_STARTUP_PATH` 时，运行文件位于该配置文件旁，隔离不同配置；相对路径以程序目录为基准。旧版守护在首次升级时仍可通过 `-Stop` 正常停止，新位置从下次手动启动生效。

日志保存在当前数据目录的 `logs/workhub/`：`supervisor.jsonl` 记录启动、退出时间、退出码、运行时长、重试安排和强制停止；`service.log` 保存服务输出、异常堆栈和 Python 致命错误信息，重启轮换保留最近 5 次运行。守护事件日志按 2 MB 轮换，保留当前和 3 份备份。系统强制杀进程时只能记录观察到的退出码，不能判断是谁终止；守护也被终止或突然断电时，下次启动会补记上次未正常结束，具体原因标记未知。

`.env.example` 默认使用 Codex 后端、独立会话上下文、群聊默认不回复、不自动标记已读。若 Codex 不在 PATH，填写 `.env` 中的 `LARKX_CODEX_PATH`。模型可通过 `LARKX_CODEX_MODEL` 配置，留空使用 CLI 默认模型。

网页只绑定 `127.0.0.1`。凭证、消息数据库、图片缓存与模型会话默认保存在程序目录下的 `data`，SQLite 默认为 `data/messages.db`，首次启动自动创建。路径以程序位置为准，不随启动时的工作目录变化。已保存的数据目录或 `LARKX_HOME` 可覆盖默认位置。这些数据不纳入 Git。不要同时启动 `lark listen --agent` 与网页监听，否则可能重复处理消息。

待办、会话、角色档案和执行记录按数据库分页查询，每页条数随窗口可用高度调整，底部分页栏保持可见。搜索和筛选覆盖全部历史；返回列表保留页码和条件，后台变化提示刷新，不自动打乱正在浏览的内容。角色说明、执行正文在侧边详情中查看；聊天消息向上加载更早记录。网页分页不受工具端已完成任务和执行记录缓存数量限制，顶部统计使用数据库总数。

在“数字人设置”可调整消息停顿时间（1–30 秒）和最长等待时间（1–60 秒），时间均以整数秒设置，人工回复后暂停以整数分钟设置；旧配置的小数向上取整。保存后下一批消息生效，重启后保留。未在网页设置时，`LARKX_BATCH_DELAY` 默认 2 秒，收到新句子后重新计时；`LARKX_BATCH_MAX_WAIT` 默认 5 秒，避免连续来消息时一直等待。一个批次初始最多 20 条，可在“消息处理”中调整。群聊按各群的回复选项触发；选择仅 @我或仅 @全体时，短暂等待期间的未 @补充句会一起理解，其他群消息不会独立触发回复。

背景分析初始每 30 秒合并处理一批消息，间隔可在“数字人设置”调整为 1–600 秒，或通过 `LARKX_BACKGROUND_INTERVAL` 配置。每个会话/话题只有一个后台处理任务，每批最多 20 条，多余消息留待后续批次；失败批次保留到下次来消息时重试。回复、润色和手动更新概览优先于排队的后台任务，默认两个模型并发名额中后台最多占一个，可在“性能与高级”调整，已开始的模型调用不会被强制打断。

同一会话的分析串行执行，包含该会话的不同话题；下一份分析在获得处理名额后才读取最新概览。按本地消息进度保存概览版本，即使旧后台批次因优先级调整而晚于新回复执行，也不会覆盖新概览，仍可补充遗漏的事实和待办。

## 操作

进入“会话与记忆”选择联系人，编辑消息后点击发送。Enter 换行，Ctrl + Enter 发送。图片最多 6 张，单张不超过 10 MB，支持 PNG、JPEG、GIF、WebP。

“角色档案”设置关系、背景、口吻与回复方式。“数字人设置”的“常规”分别配置私聊默认回复、群聊默认回复，以及回复规则和文字尾缀。单独设置优先于默认策略；“跟随默认”的对象会随默认值一起更新。AI 润色生成的草稿需要手动发送。升级保留已有联系人和群的回复行为；旧联系人无法区分历史默认值和手动设置，因此保留为单独设置，需要时可切换为“跟随默认”。新建档案自动跟随默认。

控制台的明确发送指令会执行。发送结果无法确认时保留为待核对，不自动重发；提交相同请求 ID 不会再次发送。实际编码、排期、审批等工作不会仅凭聊天请求被标记为已完成。

控制台按动作类型检查当前指令的授权：查询、总结、建议和引用内容不会授权写操作；创建待办不会同时授权完成任务或修改档案。执行时请明确表述，例如“创建一个准备排期的待办”“把任务 12 标记为已完成”“修改张三的角色为负责人”。未明确授权的模型动作会显示为已阻止。

待办列表保留全部未完成事项，已完成列表初始显示最近 300 条，可在“性能与高级”调整；已完成记录仍保存在数据库中，按任务 ID 操作不受列表数量限制。

数字人设置分为“常规、消息处理、模型与上下文、性能与高级、连接与存储”五组。每组独立保存，可切换分组保留尚未保存的内容；“恢复默认”只填入表单，点击保存后才生效。模型名称、推理强度、生成超时、上下文条数、批次大小、并发、刷新周期、模型网络重试和展示数量均可调整。连接、目录、数据库与端口为只读启动信息。

运行设置统一在 `larkx/settings.py` 定义类型、默认值、范围、说明与生效时机，前端从 `/api/settings` 获取同一份定义。有效值按“网页保存值 → 对应环境变量 → 内置默认值”读取，已有数据库设置和 `.env` 继续生效；空尾缀、空模型名称、接管等待为 0 都保留其实际含义。保存先统一校验，再在同一事务中写入。降低并发不会中断已开始的调用，新调用使用新限制；原始消息和任务不会因显示数量降低而删除。

## 模型连接

在“模型与上下文”先选择 CLI 或 API，再选择工具或服务商。当前预置 CLI：Codex、Cursor CLI、Claude Code、Qwen Code、Gemini CLI、OpenCode；API：DeepSeek、通义千问、智谱 GLM、Kimi、豆包、OpenAI、Claude、Gemini、自定义 OpenAI 兼容接口。

CLI 自动检测程序，也可填写完整路径；首次登录在各工具中完成。“检查环境”检查安装与可确认的登录状态，无法确认时明确提示；“测试调用”使用内置测试文字验证结构化输出，不会发送飞书聊天历史。API 预填基础地址，需填模型 ID（豆包等也可能需要接入点 ID）和密钥；“获取模型”可拉取服务支持的模型列表，不支持时可手动填写。千问地址可按所在地域和工作空间修改。测试不保存或激活连接，只有“保存连接”会切换当前接入。

每个工具/服务商分别保存配置，切换保留其模型、路径/地址、推理设置和密钥；新调用使用保存后的配置，已开始的调用使用原配置快照。原 Codex 环境变量及网页模型/推理配置会作为首次连接的默认值，保存新连接后按各连接配置执行。上下文条数、字数预算、生成超时和并发仍共用。

密钥在本地加密保存，接口仅返回“已设置”，空白保留原密钥，勾选清除后保存才删除；也支持相应服务商的环境变量。Windows 使用当前用户 DPAPI 保护本地加密主密钥；其他系统主密钥文件权限为 0600。不要把 `LARKX_HOME/model-key.bin` 或数据库提交到 Git。API 地址不能嵌入密钥，远程接口使用 HTTPS，请求不跟随重定向。

API 适配 OpenAI Chat Completions、Anthropic Messages 和 Gemini generateContent。模型输出经过 JSON Schema 本地校验，再进入待办/记忆与发送处理。图片理解由所选 API 模型能力决定，需手动启用；CLI 第一版仅 Codex 接入图片，其余 CLI 遇到附图会明确报错，可关闭模型图片输入或改用支持图片的接入。第三方 CLI 的版本、登录和模型权限需在本机通过“测试调用”确认；预置选项不代表已在每个服务商真实账号上测试。

## 启动配置与发送限制

消息平台下拉当前只提供飞书，沿用个人账号扫码接入。Windows 本机运行时，数据目录、SQLite 数据库和 CLI 程序路径旁提供系统“浏览”按钮。选择只回填未保存的草稿，不上传、复制或覆盖文件；取消保留原值。SQLite 可浏览选择已有数据库，也可直接填写新文件路径，文件及表会在下次启动存储时自动创建。其他系统或无法打开系统窗口的环境可继续手动填写路径。

“连接与存储”可修改数据目录、SQLite 文件或 MySQL 连接和服务端口。MySQL 分别填写主机、端口、数据库名、账号和密码，由后台生成连接地址；密码加密保存，不回显，留空保留已保存密码。保存前检查存储，当前进程继续使用原配置，下次启动生效；可撤销等待生效的修改。切换目录或数据库不会迁移旧记录，旧文件保留；新数据目录需要重新登录并配置模型密钥。MySQL 需安装 `uv sync --extra mysql`。

启动配置保存在 Windows `%LOCALAPPDATA%/LarkAgentX/startup.json`，其他系统为 `~/.config/LarkAgentX/startup.json`；可用 `LARKX_STARTUP_PATH` 指定。配置文件独立于数据目录，优先于环境变量；运行时设置仍保存在各自数据库。`lark web --print-url` 显示下次启动地址，`start-workhub.ps1` 跟随保存的端口；显式 `lark web --port` 可覆盖本次端口。端口变更后需更新外部 MCP 客户端地址。同一程序实例或同一显式启动配置目录只允许一个网页服务运行，防止修改端口后重复接收和回复消息。

连接页可重新连接，或切换飞书 / Lark 扫码登录；处理中会阻止切换，不中断现有分析。登录二维码只在打开的登录窗口中轮询，凭证验证成功后替换旧凭证。

“消息处理”可降低发送文字、图片张数和单图大小上限，默认仍为 12000 字符、6 张、10 MB，网页和后台发送统一校验。“模型与上下文”统一设置指令对话保留轮数和历史字数（默认 6 轮、8000 字符），可设为 0 轮关闭；图片回溯按普通消息 / 提及图片分别设置。API 可设置最大输出 token 数（默认 8192），CLI 的输出上限由对应工具控制。不同模型支持的 token 上限不同，需要在支持范围内填写。

## MCP 接入

启动工作台后，本机 MCP 地址为 `http://127.0.0.1:8765/mcp`，传输方式选 **Streamable HTTP**。MCP 与网页共用同一个飞书连接，不需要重新登录。当前只供本机应用访问，不支持云端应用直接连接。

仅支持 stdio 的应用，可参考 [mcp-config.example.json](mcp-config.example.json) 配置命令，修改为自己的 uv 和项目路径。实际启动命令为：

```powershell
uv run --directory E:\Myproject\LarkAgentX --no-sync python -m larkx.workhub.mcp_server
```

stdio 代理默认读取已保存的服务端口；工作台使用临时端口或不同启动配置时，在命令最后添加 `--hub-url http://127.0.0.1:其他端口`。

提供 `get_status`、`search_conversations`、`get_chat_history`、`search_messages`、`send_message` 五个工具。记录来自本机已同步的数据库，并非飞书全部历史；查询返回 `next_before_id` 可翻页，会话搜索使用 `next_offset` 翻页。

先搜索联系人或群聊，取得明确的 `chat_id`，再发送。重名会返回多个会话，不自动猜测。发送需指定消息正文和唯一 `request_id`（建议 UUID），同一发送的重试必须复用 ID。仅 `status=sent` 表示成功，`uncertain` 应先在飞书核对，不换 ID 重发。发送沿用设置中的文字尾缀，写入执行记录，并触发配置时长的人工接管（默认 2 分钟）。

客户端提示示例：“查边泽文最近 30 条聊天记录”“搜索关于上线排期的消息”“给边泽文发送：下午三点开会”。请在客户端启用发送工具的确认提示。

MCP 协议实现使用 [官方 Python SDK](https://github.com/modelcontextprotocol/python-sdk)。

## 实现与限制

`larkx/workhub` 包含 FastAPI 本地服务、SQLAlchemy 状态存储和前端静态文件；`CodexBackend` 使用独立临时目录与只读沙箱生成结构化分析。

会话列表与角色列表分别通过一次批量查询读取展示信息。启动时按联系人和会话聚合新增历史，元数据与处理进度在同一事务中保存；没有新增历史时不重放消息，也不更新会话时间或已有角色配置。

模型分析与润色每轮使用当前角色、概览、记忆、任务和近期消息，不再叠加或保存旧的完整提示词，只保留近期图片信息；控制台单独保留精简的历史指令和答复。重复消息正文只携带一次，过长背景与消息按字符预算裁剪，保留发送者、消息 ID、任务状态和当前工作规则；数据库原文不变。`LARKX_CONTEXT_BUDGET` 默认 48000 字符，可设置 24000–200000；这不是 token 数，也不包含图片。当前指令、工作规则或必需身份信息无法容纳时会报错，不会静默删掉它们。

网页初始每 5 秒按版本同步变更记录，间隔可在“性能与高级”调整，，更新消息、概览和记忆时保留编辑区与搜索条件；页面隐藏时暂停轮询。SQLite 空闲轮询只检查数据库版本，其他连接写入也能使缓存失效；其他数据库使用一秒缓存。增量缓存初始保留最多八个会话，可在“性能与高级”调整，服务重启或缓存过期会自动重新同步。原有 `/api/state` 和会话详情完整查询接口仍可使用。

个人账号消息通道依赖飞书网页私有协议，后续飞书更新可能影响登录、消息或资源上传；该项目并非飞书官方客户端。聊天历史与必要图片会作为模型上下文提交到已登录的模型服务。仅在本机环境使用，勿把控制台直接暴露到公网。

群聊“闲聊模式”会让 AI 结合上下文判断是否参与：优先回应对我说的话，别人之间的讨论通常不接话，有趣或能补充信息时可偶尔插一句，并非每条都回复。闲聊模式下真实 @我（包括单独一个 @）必须回应，仍遵守人工接管和独立回复策略。

群聊定向回应支持引用消息和真实 @个人。AI 使用当前群聊/话题中的消息 ID 和发送者 ID 选择对象，普通插话可以不指定。MCP `send_message` 可选参数 `reply_to_message_id` 与 `mention_user_id`，引用对象和 @对象会纳入重复请求校验。已在三人群实测发送，服务器回读确认引用关联和真实 @用户 ID。

Codex 失败提示会区分网络、登录、模型、额度和格式问题。仅网络错误在同一次总超时内重试一次，飞书消息仍只在成功生成后发送。结构化分析直接使用工作台提供的最新上下文，不重复拼接过去的完整背景快照。

待办按具体事项关联：AI 通过已有任务编号将后续分句、解释、附件和进展追加到同一条待办；不同问题分别建单。关联限制在当前会话和话题的未完成任务内，保留人工编辑的标题、状态、日期及草稿。相同消息批次重复分析不会重复建单；同一会话的回复分析和后台整理按顺序执行。私聊和群聊均提供本人用户 ID，后台整理不生成自动回复。

新待办必须是明确由本人负责、仍需行动的具体事项，并引用本次真实消息作为依据。普通问答、通知、结束语、表情、别人的工作和模型自身不确定不自动建单。“需要你决定”关联实际业务事项，不能单凭缺少上下文创建占位待办；已自动回复也不代表实际工作已经完成。待处理统计与待处理列表使用相同范围，进行中的任务单独显示。

模型超时和接入问题按模型来源合并为系统异常，其他处理异常按会话/话题合并，展示次数、首次和最近时间；后续成功处理会将相应异常标为“已恢复”。技术异常位于执行记录并在工作台提示，不占业务待办。发送结果不确定只保留待核对的发送记录，不重复建单或自动重发；人工核对后可在详情标记“已核对”。

仅草稿模式的自动回复保存在会话输入区上方的“AI 回复草稿”，支持使用和忽略，不占待办。使用草稿不覆盖已有输入，更新预览不改手写内容；确认发送成功后只清理已使用的那个版本，更新后的草稿仍保留。新版本替换旧草稿时，旧正文留在已归档执行记录中。

首次升级启动时会一次性整理可识别的历史“自动处理异常／会话分析异常”“审核回复”和发送核对待办。SQLite 在修改任务前将完整数据库备份到数据库所在目录的 `backups/before-task-archive-*.db`；归档另在 `hub_task_archives` 保留原字段完整快照，并在执行记录的“已归档”中查看。未完成的审核草稿转入会话草稿，发送核对沿用已有不确定发送记录。原任务保留但不计入业务待办或完成数；有明确消息来源、截止日期或不符合已知异常特征的业务事项不会自动归档。迁移使用单个事务，可重复执行，失败不会留下部分归档结果。MySQL 使用相同事务与原字段快照。

数字人设置中的“人工回复后暂停”按分钟配置，范围 0–1440 分钟，默认 2 分钟，0 关闭。对话持续期间，以双方最后一次消息重新计时；修改设置会按最后活动时间更新仍在暂停的会话，已经结束的暂停不会重新开启。到期后仅对后续新消息恢复自动回复，暂停期间的旧消息不会补发。
